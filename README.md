# Визуализатор графа зависимостей (Вариант №4)

## 1. Общее описание
CLI-инструмент на языке Python для анализа и визуализации графа зависимостей пакетов JavaScript (npm). На Этапе 4 реализовано вычисление порядка загрузки зависимостей методом постобработки графа без рекурсии.

## 2. Описание всех функций и настроек
* **Параметры командной строки (`argparse`):**
  * `--package` — имя анализируемого пакета (обязательный).
  * `--repo` — URL-адрес репозитория npm или путь к файлу тестового репозитория (обязательный).
  * `--test-mode` — флаг включения режима работы с тестовым репозиторием.
  * `--output` — имя выходного файла с изображением графа (по умолчанию `graph.svg`).
  * `--ascii` — флаг вывода зависимостей в формате ASCII-дерева.
  * `--max-depth` — максимальная глубина анализа зависимостей (по умолчанию `3`).
* **Основные функции (`src/main.py`):**
  * `parse_arguments()` — считывает опции командной строки.
  * `validate_arguments(args)` — проверяет корректность параметров.
  * `load_test_repo(file_path)` — загружает тестовый граф зависимостей из JSON-файла.
  * `fetch_npm_dependencies(package_name, repo_url)` — получает прямые зависимости пакета из реестра npm по HTTP.
  * `build_dependency_graph(start_pkg, max_depth, get_deps_func)` — строит граф зависимостей итеративным алгоритмом DFS с обработкой циклов и ограничением глубины.
  * `get_load_order(start_pkg, graph)` — вычисляет порядок загрузки пакетов (от листьев графа к корневому пакету).
  * `print_stage4_output(...)` — выводит структуру графа, циклы и порядок загрузки.

## 3. Описание команд для сборки проекта и запуска тестов
* **Сборка проекта:** не требуется (интерпретируемый язык Python).
* **Запуск проекта:** выполнить пакетный файл `run.bat` или команду:
  ```bash
  python src/main.py --package A --repo tests/test_repo.json --test-mode --max-depth 4
  ```
* **Запуск тестов:**
  ```bash
  python -m pytest
  ```

## 4. Примеры использования и сравнение с npm
При запуске `run.bat` для пакета `A` программа выводит порядок загрузки:
```text
Порядок загрузки зависимостей:
  C -> E -> D -> B -> F -> A
```
**Сравнение с реальным менеджером пакетов `npm`:**
Последовательность загрузки в утилите может отличаться от реального `npm` по следующим причинам:
1. Реальный `npm` использует механизм *hoisting* (поднятия общих пакетов в корень `node_modules`) и разрешает семантические версии (`^`, `~`), тогда как данный инструмент строит строгий граф обхода без учёта версионных конфликтов.
2. При наличии циклических зависимостей (`B -> C -> B`) утилита разрывает цикл при повторном посещении узла, а `npm` разрешает взаимные зависимости асинхронно при распаковке.
