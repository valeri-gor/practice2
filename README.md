# Визуализатор графа зависимостей (Вариант №4)

## 1. Общее описание
CLI-инструмент на языке Python для анализа и визуализации графа зависимостей пакетов JavaScript (npm). Программа строит граф зависимостей итеративным алгоритмом DFS без рекурсии, выявляет циклические зависимости, генерирует описание графа на языке **D2**, экспортирует изображение в формат SVG/PNG и выводит структуру зависимостей в виде **ASCII-дерева**.

## 2. Описание всех функций и настроек
* **Параметры командной строки (`argparse`):**
  * `--package` — имя анализируемого пакета (обязательный).
  * `--repo` — URL-адрес репозитория npm или путь к файлу тестового репозитория (обязательный).
  * `--test-mode` — флаг включения режима работы с тестовым репозиторием.
  * `--output` — имя выходного файла с изображением графа (по умолчанию `graph.svg`).
  * `--ascii` — флаг вывода зависимостей в формате ASCII-дерева.
  * `--max-depth` — максимальная глубина анализа зависимостей (по умолчанию `3`).
* **Основные функции (`src/main.py`):**
  * `parse_arguments()` — считывает опции командной строки.
  * `validate_arguments(args)` — проверяет корректность параметров.
  * `load_test_repo(file_path)` — загружает тестовый граф из JSON-файла.
  * `fetch_npm_dependencies(package_name, repo_url)` — получает прямые зависимости пакета из реестра npm по HTTP.
  * `build_dependency_graph(start_pkg, max_depth, get_deps_func)` — строит граф зависимостей итеративным DFS с обработкой циклов и ограничением глубины.
  * `generate_d2_text(graph)` — формирует текстовое представление графа на языке диаграмм D2.
  * `save_graph_image(d2_text, output_path)` — вызывает CLI-утилиту `d2` для рендеринга SVG/PNG (или сохраняет исходник `.d2`).
  * `print_ascii_tree(start_pkg, graph)` — выводит граф в консоль в формате ASCII-дерева без рекурсии.

## 3. Описание команд для сборки проекта и запуска тестов
* **Сборка проекта:** не требуется (интерпретируемый язык Python). Для рендеринга `.svg`/`.png` опционально используется утилита `d2`.
* **Запуск проекта:** выполнить пакетный файл `run.bat` (демонстрирует 3 различных пакета) или команду:
  ```bash
  python src/main.py --package A --repo tests/test_repo.json --test-mode --output graph_A.svg --ascii --max-depth 4
  ```
* **Запуск тестов:**
  ```bash
  python -m pytest
  ```

## 4. Примеры использования и сравнение со штатными средствами
При запуске `run.bat` визуализируются три пакета (`A`, `B`, `F`). Пример вывода для пакета `A`:
```text
Представление графа на языке D2:
direction: down
"A" -> "F"
"A" -> "B"
...
ASCII-дерево зависимостей:
A
├── F
│   └── D
│       └── E
└── B
    ├── D
    │   └── E
    └── C
        └── B (цикл)
```
**Сравнение с визуализацией штатными средствами (`npm ls` / `npm explain`):**
1. Штатная команда `npm ls --all` строит дерево на основе фактически установленной папки `node_modules`, применяя дедупликацию (*hoisting*), из-за чего общие поддеревья (например, пакет `D -> E`) отображаются с пометкой `deduped` только один раз, тогда как наша утилита разворачивает полную структуру связей каждого узла.
2. При обнаружении циклической зависимости (`B -> C -> B`) штатный вывод `npm` скрывает повторную ветку или ограничивает глубину без явного графового ребра, тогда как формат **D2** позволяет отобразить замкнутый цикл в виде полноценного ориентированного графа.
